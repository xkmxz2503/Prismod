客户端 API：按用途记忆

外部模组只依赖 FilterClientApi。实现类属于内部适配器。

规范入口

注册与注销

registerCustomFilter(...) 返回 FilterRegistration；结束时调用 close()。

规范入口

选择与强制

setSessionSelection(...) 是临时选择；setForcedFilter(...) 优先级更高。

规范入口

覆盖

createOverride(...) 返回覆盖句柄，按 priority 决定生效项。

查询

快照与列表

snapshot() 读取最终渲染视图；filters() 读取滤镜描述。

监听

状态与事件

subscribe(...) 和 subscribeEvents(...) 返回订阅句柄。

兼容入口

Deprecated 方法

registerCustomFilterOperation(...)、createOverrideOperation(...) 保留但新代码不使用。

服务端 API：发布策略，不负责画面

FilterServerApi服务端模组
→
ServerFilterApplication保存策略 / generation
→
PolicyTransport业务传输端口
→
PolicyNetworkForge 网络实现
→
客户端 API落地为选择或覆盖

服务端的 OperationResult 表示服务器接受并保存了策略，不表示客户端已经完成渲染。客户端最终结果要用 FilterClientApi.snapshot() 查看。

请求模型

FilterSelectionRequest 和 FilterOverrideRequest 会在创建时校验资源标识、归一化强度；覆盖请求还要求非空 ownerId。

作用域

broadcast* 面向所有玩家，send* 面向指定玩家；相同 owner 会更新已有覆盖。

句柄与 Operation

注册 / 创建覆盖表达意图
→
生命周期句柄Registration / Override
→
operation()QUEUED → SUCCESS / FAILED
→
close()结束生命周期
不关心结果

使用普通 void 入口，例如 setForcedFilter(...)。

需要观察结果

使用 ...Operation(...)，观察排队、完成和失败原因。

重复关闭没有副作用；排队期间关闭不会取消已提交的创建。

外部模组只需要守住这些边界

可以调用

FilterClientApi、FilterServerApi 及其公开契约类型。

不要调用

ClientFilterApplication、FilterManager、FilterController、FilterRegistry。

读取状态

优先读取不可变的 FilterSnapshot，不要读取内部状态对象。

关闭资源

保存并关闭注册、覆盖、订阅和 Owner 会话句柄。

服务器隔离

专用服务器不得加载 api.client 或 net.minecraft.client。

协议区别

逻辑滤镜 ID 与 PostChain 资源路径用途不同，不能混用。
