先分清输入和查询

输入 · submit

接收明确类型的业务请求。

注册、选择、覆盖、订阅、创建会话、释放资源。

CompletionStage<FilterReceipt>

执行后给一次最终回执，不提供后续查询。

查询 · query

读取最近发布的不可变数据。

状态快照、滤镜列表、资源详情、owner 和会话资源。

<R> R query(FilterQuery<R>)

不会修改状态，也不会创建资源或订阅。

回执结束，资源继续存在

query(new FilterQuery.Resource(id))

资源存在不代表当前赢得覆盖优先级；最终效果看 Snapshot。

业务结束，释放资源

submit(new FilterRequest.Release(id))

释放后查询为空。重复释放成功，影响数量为零。

回执是固定的数据，没有 close() 或 operation()。业务成功也不等于 GPU 已经渲染成功。

按需展开，不必一次记住

注册与注销

Register 注册自定义 PostChain，Release 注销单个注册，ClearRegistrations 按 owner 清理。

逻辑滤镜使用 namespace:path；postEffect 使用实际 JSON 资源路径。旧注册资源不能注销替换后的新版本。

临时选择、强制与覆盖

Select / ClearSelection 控制临时选择，不写玩家配置。Force / ClearForced 管理旧式强制状态。Override 支持 owner 和 priority，同优先级较新者胜出。

Snapshot 查询最终效果与回退原因。

状态和事件监听

SubscribeState / SubscribeEvents 建立订阅，回执返回订阅 UUID，Release 取消。

回调在客户端线程执行，异常隔离；不补发初始快照。需要初始状态时单独 query。操作完成事件通过 receipt() 提供最终回执。

Session 与批量操作

OpenSession 创建会话；Batch 只接收 Register 和 Override，按顺序执行、允许部分成功。

ClearSession 清空后可复用；CloseSession 关闭后拒绝新增。只管理自身资源，不影响同 owner 的其他会话。

曝光、饱和度等调参

客户端请求可以携带可选的 FilterAdjustments 稀疏参数对象。例如 FilterAdjustments.builder().exposure(25).build() 只修改曝光，未填写字段保持当前值；clearExposure() 恢复继承调试预设。

现有 FilterDebugSettings 保持内部位置。服务端和网络协议暂不接入调参。

最小示例：强制 → 查询 → 恢复

var filter = ResourceLocation.fromNamespaceAndPath("prismod", "vintage");

FilterClientApi.submit(new FilterRequest.Force(filter, 75.0F))
    .thenAccept(receipt -> {
        var snapshot = FilterClientApi.query(new FilterQuery.Snapshot());
        // 根据 receipt 的状态和反馈代码处理失败。
    });

// 在业务结束时恢复普通选择。
FilterClientApi.submit(new FilterRequest.ClearForced());

仅限物理客户端调用。不要在客户端线程阻塞等待异步结果。完整 imports 和资源管理示例见 Java API 规范。

服务端，也使用两个入口

submit · 保存策略

选择、覆盖、清理。

CompletionStage<OperationResult>

服务端线程执行，保存状态后交付一次最终回执。成功不代表客户端收到或画面完成。

query · 查看服务端

Status / FilterStatus。

query(ServerFilterQuery<R>)

读取不可变服务端状态，不远程查询客户端。

执行选择或覆盖
两个 ID，解决覆盖更新

requestId：这一次请求，每次更新都不同。
policyId：持续策略，同范围同 owner 更新保持不变。

同策略同请求不重复执行；同策略新请求释放旧覆盖并创建新覆盖。排队中的旧请求完成后只释放自己的 UUID。清理只影响网络资源，保留其他模组本地覆盖。

登录补发、失败与兼容

登录补发复用策略 ID、新生成请求 ID；个人选择保持优先。服务器不可用返回 UNAVAILABLE，指定玩家离线返回 NOT_FOUND；重复清理成功且影响数量为零。

旧服务端方法已删除；协议 3 拒绝协议 2 及更早版本。断线重置映射，旧连接回执不能改写新连接状态。不增加客户端回执、重试、乱序恢复或远程调参。

源码位置与依赖边界

api/client/FilterClientApi.java：公开两个业务入口。
api/client/submit/：request 请求、model 输入数据、result 回执、listener 回调、event 通知。
api/client/query/：request 查询请求、view 只读视图。
client/application、client/filter、client/render：内部实现，不供外部模组调用。

监听通过 submit 建立，通知复用 query.view 的不可变快照。专用服务器不得加载 api.client 或 net.minecraft.client。滤镜只作用于世界画面和手持物品，不进入 HUD、聊天、菜单或容器。

服务端源码与契约

api/server/FilterServerApi.java 保留在根目录；submit/model、submit/request、submit/result 保存目标、请求和回执；query/request、query/view 保存查询和不可变状态。api/common 只保留两端共同依赖的反馈代码、操作状态和失败分类；客户端描述与渲染状态归入 api/client，公共层不负责模型转换。

FilterServerApi → ServerFilterApplication → PolicyTransport → PolicyNetwork。频道及协议常量统一来源为 PolicyTransport，协议消息为 operation、requestId、policyId、owner、filter、strength、priority。

不开放远程注册、Session、订阅、批量或客户端状态查询。管理命令语法和 OP 权限保持不变。

参数单位

客户端 API、服务端 API、命令和协议的 strength 使用 0-100 百分制；高级参数按字段语义使用百分制：曝光 -100 到 100、对比度和饱和度 0 到 200、gamma 10 到 300，其余方向型参数 -100 到 100。只有渲染边界再转换为 shader 原有范围。
