# Prismod 统一资源包格式 v1

Prismod 只扫描 `config/prismod/resourcepacks/` 的直接子目录和 `.zip` 文件。这是 Prismod 私有格式，不是 Minecraft 原版资源包：不需要 `pack.mcmeta`，也不进入原版资源包界面。

模组内置滤镜也遵循相同的 v1 目录和清单约定，完整默认包源码位于 `src/main/resources/assets/prismod/custom/prismod_default_filters/`；该目录内包含包清单、`assets/prismod/filters/`、`assets/prismod/lang/` 和 `assets/prismod/runtime/`，与 TACZ 的 `assets/<mod>/custom/<默认包>` 形式一致。滤镜名称翻译必须随资源包放在 `assets/<namespace>/lang/`，不依赖模组外层语言文件；外层 `assets/prismod/lang/` 仅用于 Prismod 自身界面、按键和消息。

首次启动客户端时，模组会把内置包导出到 `config/prismod/builtin/prismod_default_filters/`，之后按普通目录资源包读取。导出会保留 `filters/`、`lang/` 中的已有编辑；`assets/prismod/runtime/` 下的运行时处理器会随模组版本同步更新，避免旧 shader 清单导致 LUT 调试失败。修改滤镜后使用 F3+T 或重新进入世界触发 Prismod 自己的重载。

旧版 `prismod.meta.json` 和 `assets/<namespace>/shaders/...` 自动扫描格式已废弃，不会自动转换。

## 1. 根清单与目录

根目录必须有 `prismod.pack.json`：

```json
{
  "schema": "prismod.resource_pack",
  "format_version": 1,
  "namespace": "example",
  "name": "示例滤镜",
  "filters": [
    {"id": "cinematic", "path": "assets/example/filters/cinematic"},
    {"id": "grayscale", "path": "assets/example/filters/grayscale"}
  ]
}
```

`namespace` 不能是 `minecraft` 或 `prismod`；`id` 必须是合法资源路径且不能重复；`path` 必须位于当前 namespace 的 `filters/` 下。未知字段在同一版本中忽略，清单之外的目录不会被读取。可选 `dependencies` 仍支持 Forge 模组版本范围。

```text
example-resource-pack/
├─ prismod.pack.json
└─ assets/example/
   ├─ filters/
   │  ├─ cinematic/filter.json
   │  └─ grayscale/
   │     ├─ filter.json
   │     ├─ post.json
   │     └─ program/{grayscale.json,grayscale.fsh,fullscreen.vsh}
   └─ lang/
      ├─ zh_cn.json
      └─ en_us.json
```

## 2. filter.json

每个滤镜目录必须有 `filter.json`。GLSL：

```json
{"schema":"prismod.filter","format_version":1,"type":"post_chain","display_name":"filter.example.grayscale","source":"post.json","default_strength":1.0}
```

LUT：

```json
{"schema":"prismod.filter","format_version":1,"type":"lut3d","display_name":"filter.example.cinematic","source":"lut.cube","color_space":"srgb","default_strength":1.0}
```

`display_name` 是必选翻译键；`default_strength` 可选且范围为 `0.0-1.0`；引用路径不能跨滤镜目录、namespace 或穿越路径。

语言文件是 JSON 对象，例如 `assets/example/lang/zh_cn.json`：

```json
{
  "filter.example.grayscale": "黑白"
}
```

资源包重载时，Prismod 会把当前语言和 `en_us` 的语言文件加载到自己的显示翻译表中；当前语言优先，缺少当前语言时回退 `en_us`。两个文件都没有该键时界面显示完整滤镜 ID（例如 `example:grayscale`）。这张翻译表只服务于 Prismod 滤镜 UI/F8 显示，不会注册到 Minecraft 全局 `LanguageManager`，也不会借用模组 `assets/prismod/lang/` 的滤镜键。

## 3. post_chain

`source` 指向当前滤镜目录下的 PostChain JSON。它必须包含一个 `swap` target 和一个 `minecraft:main -> swap` pass。需要显示调试入口时，pass、program JSON 和 GLSL 必须同时声明以下 9 个 float uniform：`Intensity`、`Exposure`、`Contrast`、`Highlights`、`Shadows`、`Saturation`、`Temperature`、`Tint`、`Gamma`。缺少任意一个时滤镜仍可正常渲染，但会记录资源校验错误且不显示调试入口。program JSON 和 GLSL 只允许位于当前滤镜目录的 `program/` 下。

## 4. lut3d 与 .cube

Adobe `.cube` 必须是 3D LUT：`LUT_3D_SIZE` 支持 1 到 64，RGB 数据点数量必须是尺寸的三次方，`color_space` 固定为 `srgb`。默认模板使用 32³。支持注释、`TITLE`、`DOMAIN_MIN`、`DOMAIN_MAX`；缺少域范围时使用 `0..1`。未知指令、尺寸超出 1 到 64、点数错误、非有限值和非法范围会拒绝滤镜；0 没有可渲染的数据点，也会被拒绝。强度 0 为原画面，1 为完整 LUT，中间值为插值。

## 5. 导入、启用与重载

可以在 Prismod 的“资源包管理”页面拖入目录或 ZIP，也可以手动放入上述目录。保存后由 Prismod 私有资源管理器重新读取，不调用 Minecraft 原版资源包重载。错误 schema、版本、namespace、路径、重复 ID、损坏 ZIP 或缺少 `filter.json` 的资源包会被跳过；未知滤镜类型只跳过对应条目。

资源包管理页的“创建资源包”入口会生成一个空的 Prismod v1 目录包。向导填写显示名称、namespace，并可选择生成根目录 `README.md`；生成结果类似：

```text
config/prismod/resourcepacks/example/
├─ prismod.pack.json
└─ README.md
```

创建向导不会生成滤镜、语言文件或 shader。创建完成后，在资源包编辑页使用“新建滤镜”手写模板，或导入已有滤镜。创建不使用 `pack.mcmeta`，也不接入 Minecraft 原版资源包管理器；namespace 冲突或目标目录已存在时不会覆盖文件。

资源包编辑页的语言编辑可以按需创建中文 `zh_cn` 或英文 `en_us` 语言文件模板。模板内容是空 JSON 对象，只加入当前编辑草稿；返回主编辑页点击保存后才写入磁盘，已有同名语言文件不会被覆盖。

资源包条目右侧的“编辑”按钮会打开常用编辑页。主页面支持包显示名称、namespace 和抽象滤镜信息；README、按语言分类的滤镜显示名称以及 `prismod.pack.json`、`filter.json`、PostChain/program JSON、GLSL、`.cube` 等原始文件分别通过独立入口编辑，其中原始文件属于“高级文件编辑”。子页面只修改共享草稿，主页面点击保存后才执行校验、备份和原子替换。ZIP 会解压为同名 `.editable` 目录并保留原 ZIP；namespace 修改会另存为同级新目录，目标 namespace 已存在时不会覆盖。滤镜新增、重命名和删除会同步管理清单与滤镜目录，删除内容在保存时放入包内 `.prismod-recycle/`。

点击保存前会重新校验清单、路径、滤镜引用和 JSON 结构，校验失败不会写盘；通过校验后使用临时目录和备份执行原子保存，并触发 Prismod 私有资源重载。取消、关闭或窗口重建不会保存草稿。资源包编辑页的“新建 PostChain”和“新建 LUT”会进入滤镜预设向导：可填写 ID、默认强度、各语言显示名称，并拖入完整滤镜目录或单个 `.cube`、`post.json`、program JSON、GLSL 文件。向导会自动生成可运行模板，PostChain 包含完整 pass、program、顶点/片段 shader 和九个调试 uniform，LUT 默认使用 32³ identity 数据；导入的 LUT 可使用 1 到 64 的实际尺寸，保存和渲染会按尺寸处理，0 尺寸会被拒绝。导入文件只覆盖对应模板，显式缺少引用或契约校验失败时阻止加入草稿。

## 6. 滤镜调试界面

在世界内打开“滤镜设置”，找到支持统一 uniform 契约的 LUT 或 `post_chain` 滤镜行并点击“调试”即可临时预览。调试页不会改写当前滤镜选择、普通滤镜强度或 `.cube` 原文件；关闭页面后恢复普通滤镜状态。

调试参数包括预览强度（0-1）、曝光（-2 至 2 EV）、对比度、高光、阴影、色温和色调（-1 至 1）、饱和度（0-2）以及伽马（0.1-3）。处理顺序为曝光、色温/色调、伽马、LUT、对比度、高光/阴影、饱和度，最后按预览强度与原画面混合。所有输入都会进行有限值检查和范围裁剪。

点击“保存预设”后，参数写入 `config/prismod/config/resourcepacks/<namespace>/<filter-id>.json`。例如 `example:cinematic` 写入 `config/prismod/config/resourcepacks/example/cinematic.json`，文件格式如下：

```json
{"schema":"prismod.filter_debug","format_version":1,"filter":"example:cinematic","settings":{"intensity":1.0,"exposure":0.0,"contrast":0.0,"highlights":0.0,"shadows":0.0,"saturation":1.0,"temperature":0.0,"tint":0.0,"gamma":1.0}}
```

保存按钮才落盘，取消、关闭和窗口重建不会写入临时修改。预设与 Forge TOML 配置分离；资源包暂时删除时预设仍保留，资源包重新出现后可继续使用。旧 `lut-presets.json` 不读取。解析、纹理上传或渲染失败时保留原始世界画面，并在调试页诊断栏显示最近错误。
