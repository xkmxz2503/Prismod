# Prismod 自定义滤镜资源包制作说明

Prismod 只扫描游戏目录 `config/prismod/resourcepacks/` 的直接子目录和 `.zip` 文件，不读取原版 `resourcepacks/` 中的 Prismod 资源。资源包不需要在 Minecraft 资源包界面中启用。

## 1. 目录结构

资源包根目录必须包含固定文件名 `prismod.meta.json`：

```json
{
  "namespace": "example"
}
```

`namespace` 必须符合 Minecraft 命名空间规则，且不能是 `minecraft` 或 `prismod`。也可以声明可选的模组版本依赖：

```json
{
  "namespace": "example",
  "dependencies": {
    "some_mod": ">=1.0.0"
  }
}
```

目录资源包和 ZIP 的根目录都必须直接包含元数据文件和 `assets`：

```text
config/prismod/resourcepacks/example-resource-pack/
├─ prismod.meta.json
└─ assets/example/shaders/
```

后处理 JSON 放在 `assets/<命名空间>/shaders/post/`，对应的 program JSON、GLSL 文件放在 `assets/<命名空间>/shaders/program/`。

## 2. 后处理 JSON 契约

`post/debug.json` 至少需要一个 `swap` target 和一个 pass：

```json
{
  "targets": ["swap"],
  "passes": [
    {
      "name": "example:debug",
      "intarget": "minecraft:main",
      "outtarget": "swap",
      "uniforms": [{"name": "Intensity", "type": "float", "values": [1]}]
    }
  ]
}
```

Prismod 会检查 target、pass、program 资源以及 `Intensity` float uniform。单个滤镜或资源包损坏时只跳过对应资源，不会导致游戏崩溃。

## 3. ID、排序和重载

资源路径 `assets/example/shaders/post/debug.json` 对应滤镜 ID `example:debug`。资源包按文件名升序扫描；相同滤镜 ID 由文件名较大的资源包覆盖。

放入、删除或修改资源包后执行 F3+T，滤镜列表和当前渲染状态会同步重建。非法 JSON、缺少元数据、非法命名空间、损坏 ZIP 或不满足依赖的资源包会记录日志并跳过。
