# Prismod 自定义模组资源包制作说明

Prismod 只扫描游戏目录 `config/prismod/resourcepacks/` 的直接子目录和 `.zip` 文件。这是 Prismod 自己的模组资源包格式，不是 Minecraft 原版资源包：不需要 `pack.mcmeta`，也不读取原版 `resourcepacks/` 目录，更不需要在 Minecraft 资源包界面中启用。

## 1. 目录结构

资源包根目录必须包含固定文件名 `prismod.meta.json`：

```json
{
  "namespace": "example",
  "name": "示例滤镜"
}
```

`namespace` 必须符合 Minecraft 命名空间规则，且不能是 `minecraft` 或 `prismod`。`namespace` 是资源包在 Prismod 配置中的稳定 ID；可选的 `name` 用于管理界面显示名称。也可以声明可选的模组版本依赖：

```json
{
  "namespace": "example",
  "dependencies": {
    "some_mod": ">=1.0.0"
  }
}
```

目录资源包和 ZIP 的根目录都必须直接包含 Prismod 元数据文件和 `assets`。可以额外放置 README、文档、许可证或其它资源目录；校验时只读取元数据和元数据 namespace 对应的 `assets/<namespace>/` 相对目录，其它文件不会被 Prismod 读取：

```text
config/prismod/resourcepacks/example-resource-pack/
├─ prismod.meta.json
├─ README.md
├─ docs/
└─ assets/example/shaders/
```

后处理 JSON 放在 `assets/<命名空间>/shaders/post/`，对应的 program JSON、GLSL 文件放在 `assets/<命名空间>/shaders/program/`。

## 2. 后处理 JSON 契约

`post/debug.json` 至少需要一个 `swap` target 和一个 pass：

```json
{
  "targets": ["swap"],
  "passes": [
    {
      "name": "example:debug",
      "intarget": "minecraft:main",
      "outtarget": "swap",
      "uniforms": [{"name": "Intensity", "type": "float", "values": [1]}]
    }
  ]
}
```

Prismod 会检查 target、pass、program 资源以及 `Intensity` float uniform。单个滤镜或资源包损坏时只跳过对应资源，不会导致游戏崩溃。它不是 Minecraft 原版资源包，不需要 `pack.mcmeta`。

## 3. ID、排序和重载

资源路径 `assets/example/shaders/post/debug.json` 对应滤镜 ID `example:debug`。资源包按文件名升序扫描；相同滤镜 ID 由文件名较大的资源包覆盖。

可以在 Prismod 滤镜设置的“资源包管理”二级页面直接将目录资源包或 ZIP 拖入窗口导入，也可以点击“打开资源包文件夹”后手动放入 `config/prismod/resourcepacks/` 目录。导入会校验元数据、依赖、命名空间唯一性和 `assets/<namespace>/` 路径，并在成功后刷新列表；随后可启用/禁用资源包。在独立的“滤镜管理”二级页面控制单个滤镜是否展示。同名目标不会覆盖。保存资源包设置后会立即触发资源重载。非法 JSON、缺少元数据、非法命名空间、重复命名空间、损坏 ZIP 或不满足依赖的资源包会显示失败原因并记录日志、跳过。系统无法自动打开目录时，可直接在文件管理器中进入该路径放置资源包。
