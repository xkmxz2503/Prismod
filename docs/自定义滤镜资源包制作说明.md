# Prismod 自定义滤镜资源包制作说明

本文说明如何制作能被 Prismod 自动发现的客户端滤镜资源包。资源包只提供已有的 Minecraft 后处理资源，不需要修改 Prismod 源码。

## 1. 目录结构

滤镜后处理 JSON 必须放在以下路径：

```text
assets/<命名空间>/shaders/post/<滤镜路径>.json
```

对应的 program JSON 和 GLSL 文件通常放在：

```text
assets/<命名空间>/shaders/program/<程序名>.json
assets/<命名空间>/shaders/program/<程序名>.fsh
assets/<命名空间>/shaders/program/<顶点程序>.vsh
```

例如 `example:debug` 应包含：

```text
assets/example/shaders/post/debug.json
assets/example/shaders/program/debug.json
assets/example/shaders/program/debug.fsh
```

资源包仍需包含标准的 `pack.mcmeta`，并通过 Minecraft 的资源包界面启用。

## 2. 后处理 JSON 契约

`post/debug.json` 至少应满足以下结构：

```json
{
  "targets": ["swap"],
  "passes": [
    {
      "name": "example:debug",
      "intarget": "minecraft:main",
      "outtarget": "swap",
      "uniforms": [
        {
          "name": "Intensity",
          "type": "float",
          "values": [1]
        }
      ]
    }
  ]
}
```

Prismod 会检查：

1. 只有一个 `swap` target。
2. 只有一个 pass。
3. pass 的输入是 `minecraft:main`，输出是 `swap`。
4. pass 声明 `Intensity` float uniform。
5. `name` 指向的 program JSON 存在，且 program 也声明 `Intensity` float uniform。
6. 对应 shader 能被 Minecraft 正常加载和链接。

多 pass、错误 target、非法 JSON、缺少 program 或缺少 `Intensity` 的滤镜会显示为不可用，并且不会进入实际循环。

## 3. Program JSON 与 GLSL

program JSON 的 fragment shader 可以使用任意已有的后处理写法，但必须声明 `Intensity`：

```json
{
  "vertex": "example:fullscreen",
  "fragment": "example:debug",
  "attributes": ["Position"],
  "samplers": [{"name": "DiffuseSampler"}],
  "uniforms": [
    {
      "name": "Intensity",
      "type": "float",
      "count": 1,
      "values": [1]
    }
  ]
}
```

fragment shader 应使用 `Intensity` 控制原图与效果的混合强度，并保留原图 alpha。例如：

```glsl
#version 150
uniform sampler2D DiffuseSampler;
uniform float Intensity;
in vec2 texCoord;
out vec4 fragColor;

void main() {
    vec4 source = texture(DiffuseSampler, texCoord);
    vec3 effect = vec3(1.0) - source.rgb;
    fragColor = vec4(mix(source.rgb, effect, clamp(Intensity, 0.0, 1.0)), source.a);
}
```

实际项目中建议像内置滤镜一样使用 `ScreenSize` 处理半像素边界，并确保 `Intensity = 0` 时输出原图。

## 4. 名称与 ID

滤镜 ID 由后处理 JSON 的资源路径生成：

```text
assets/example/shaders/post/debug.json -> example:debug
assets/example/shaders/post/debug/scan.json -> example:debug/scan
```

显示名称优先使用翻译键：

```text
filter.example.debug
filter.example.debug.scan
```

没有对应翻译时，界面显示完整 ID，例如 `example:debug`。

## 5. 重载与故障处理

启用、禁用或更新资源包后执行资源重载。Prismod 会重新扫描并校验资源。

单个滤镜加载、链接或渲染失败时：

- 日志包含该滤镜 ID 和失败原因。
- 该滤镜标记为不可用并从循环候选中跳过。
- 当前画面回退到原画。
- 其他滤镜继续可用。

资源恢复后再次重载，滤镜会自动恢复。配置中的未知自定义 ID 和强度不会被自动删除。

## 6. 配置示例

客户端配置中的 `cycle_order` 可以使用完整 ID，也兼容内置短名称：

```toml
cycle_order = ["original", "prismod:grayscale", "example:debug"]
```

自定义强度使用 `namespace:path=value`：

```toml
custom_strengths = ["example:debug=0.75"]
```

重复强度条目取最后一个有效值，强度会限制在 `0.0` 到 `1.0`。
